## 🛠️ รายละเอียดการทำงานแต่ละส่วน (Technical Breakdown)

### 1. การเปลี่ยนผ่านสู่ระบบจริง (API Integration)
* **งานที่ต้องทำ**:
  * ตรวจสอบไฟล์ `src/config.ts` เพื่ออัปเดต `API_URL` ให้ชี้ไปยัง Google Apps Script Web App URL ตัวจริง
  * จัดการมาตรการ Rate Limits และข้อจำกัดการเขียนข้อมูลใน Google Sheets พร้อมทำระบบแจ้งเตือนเมื่อเกิดความผิดพลาดในการเรียกใช้ API
* **คำแนะนำ**:
  * ควรใช้ `useAppStore` ในการจัดการสถานะการโหลด (Loading States) และการแจ้งเตือน Error ทั่วทั้งระบบ เพื่อให้ UI ดูไหลลื่น

### 2. พัฒนาระบบ Tracking Links (External Redirection)
* **งานที่ต้องทำ**:
  * ในหน้ารายงานไปรษณีย์ภายนอก ([PublicTrackView.tsx](file:///D:/%5BDEV%5D%20__WUS_Track_DB/src/components/auth/PublicTrackView.tsx) บรรทัดที่ 394) ให้พัฒนาฟังก์ชันรับหมายเลข Tracking เพื่อตรวจจับค่ายขนส่ง (Regex Detection) และสร้างปุ่มลิงก์นำทางไปยังระบบเช็คพัสดุจริง
  * ตัวอย่างการลิงก์สำหรับไปรษณีย์ไทย:
    `https://track.thailandpost.co.th/?trackNumber={TRACKING_NO}`
* **คำแนะนำ**:
  * ใช้ชุดข้อมูลผู้ให้บริการหลัก เช่น ไปรษณีย์ไทย, Kerry/Flash Express เพื่อสร้าง Dynamic Link

### 3. เสริมความสามารถ PWA และระบบ Offline
* **งานที่ต้องทำ**:
  * ปรับปรุงไฟล์ `manifest.json` เพื่อรองรับโหมด "standalone" ในอุปกรณ์เคลื่อนที่
  * ในกรณีที่ระบบเชื่อมต่ออินเทอร์เน็ตขาดหาย (Offline) ให้ระบบบันทึกงานเก็บลงใน IndexedDB ผ่าน `syncEngine.ts` ทันที และใช้ Event `online` ในการสั่งส่งข้อมูลที่ค้างอยู่ (Pending Logs) ขึ้นระบบ Sheets ทันทีเมื่อสัญญาณกลับมา
* **คำแนะนำ**:
  * ปฏิบัติตาม **GGSheet Protocol** โดยทำระบบ Optimistic UI Updates (แสดงรายการว่าเพิ่มแล้วทันทีในตาราง แม้จะยังซิงก์ไม่เสร็จสิ้น) เพื่อลดความรู้สึกหน่วงของผู้ใช้

### 4. การทดสอบอัตโนมัติแบบครอบคลุม (E2E Test Coverage)
* **งานที่ต้องทำ**:
  * เพิ่มขอบเขตการเขียนสคริปต์ Playwright ใน [playwright-test-sanity.js](file:///C:/Users/Admin/.gemini/antigravity-cli/scratch/playwright-test-sanity.js) ให้ทดสอบส่วนงานของเจ้าหน้าที่หลัก (Staff View) เช่น การล็อกอินด้วยอีเมล, การบันทึกรอบวิ่งรับเอกสาร, และการกดออกรายงาน
  * ตั้งค่า GitHub Actions ให้สั่งรันชุดทดสอบ Playwright เสมอก่อนจะทำการ Merge หรือ Deploy งาน

## 📝 รายการตรวจสอบความพร้อมก่อนขึ้นระบบ (Deployment Checklist)

- [ ] ทดสอบความเข้ากันได้ของโหมดมืด (Dark Mode Contrast) ทุกหน้าเพจด้วยเครื่องมือ `npx impeccable detect src/`

- [ ] จัดทำเอกสารแนะนำสำหรับผู้ใช้งานระบบคัดแยกพัสดุหลัก
