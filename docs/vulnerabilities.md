# Security Vulnerabilities & Remediation / รายงานช่องโหว่ด้านความปลอดภัยและแนวทางแก้ไข

เอกสารนี้รวบรวมข้อบกพร่องและจุดอ่อนด้านความปลอดภัยของข้อมูล (Security Vulnerabilities) ที่ตรวจพบในระบบ **WUS Track DB System** ทั้งในส่วนของระบบปลายทางหลังบ้าน (Google Apps Script API) และส่วนติดต่อผู้ใช้งานด้านหน้า (React Client-side UI) พร้อมรายละเอียดการแก้ไขเสร็จสมบูรณ์

---

## 🔒 1. การข้ามระบบตรวจสอบตัวตนฝั่งไคลเอนต์ (Client-Side Login Bypass)
* **รหัสอ้างอิง:** SEC-01
* **ผลการตรวจสอบ (Observation):**
  * เดิมทีฟังก์ชันการล็อกอินถูกตรวจสอบในระดับเบราว์เซอร์ของผู้ใช้เท่านั้น โดยใช้เพียงแค่อีเมลในการเทียบหาความตรงกันจากตัวแปร `masterData.users` ที่ได้จากเซิร์ฟเวอร์โดยไม่มีการเทียบรหัสผ่านหรือโทเค็นความปลอดภัยใด ๆ ทำให้อีเมลหรือ ข้อมูลล็อกอินถูกแก้ไขใน `localStorage` เพื่อแอบอ้างสิทธิ์ของผู้อื่นได้ง่าย
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ติดตั้งระบบ Google Sign-in / OIDC สำหรับยืนยันตัวตนจริงร่วมกับ Google ID Token
  * ดำเนินการย้ายตรรกะการตรวจสอบเซสชันทั้งหมดไปทำงานฝั่งเซิร์ฟเวอร์ (Google Apps Script Backend)
  * ออก `sessionToken` ที่มีความปลอดภัยสูงจากแบ็กเอนด์เมื่อล็อกอินสำเร็จ และนำมาเก็บใน Zustand Store + LocalStorage เพื่อส่งแนบกับทุกคำขอ API ในอ็อบเจกต์ `auth`

## 📡 2. การเปิดเผยข้อมูลภายในต่อสาธารณะโดยไม่มีการตรวจสอบสิทธิ์ (Unauthenticated Public Endpoints & Data Leaks)
* **รหัสอ้างอิง:** SEC-02
* **ผลการตรวจสอบ (Observation):**
  * ฟังก์ชัน `doGet(e)` ปล่อยให้บุคคลทั่วไปเรียกเข้าถึงและขอรับชุดข้อมูลทั้งหมด (Metadata Dump) เช่น รายชื่อพนักงาน และข้อมูลธุรกรรมได้โดยไม่มีการตรวจสอบตัวตน
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ปรับปรุงให้ `doGet(e)` แสดงผลเพียงข้อความสถานะ `"DCG Smart Track API is running."` และไม่อนุญาตให้ดึงข้อมูลใด ๆ
  * ย้ายคำสั่งการดึงข้อมูล `getMetaData` และ `searchLogs` ไปอยู่ในคำขอแบบ `doPost` พร้อมทั้งบังคับตรวจสอบสิทธิ์ผ่านฟังก์ชัน `verifySessionToken` ทุกครั้ง

---

## 💉 3. ช่องโหว่การฝังสูตรคำนวณสเปรดชีตประสงค์ร้าย (Formula / CSV Injection Risk)
* **รหัสอ้างอิง:** SEC-03
* **ผลการตรวจสอบ (Observation):**
  * ข้อมูลนำเข้าที่เป็นข้อความอิสระ (ปัญหา, หัวข้อ, หรือรายละเอียด) ถูกเขียนลงในเซลล์สเปรดชีตโดยไม่มีการแปลงอักขระควบคุม (เช่น `=`, `+`, `-`, `@`) ซึ่งอาจทำให้ถูกสั่งรันสูตรคำนวณประสงค์ร้ายเพื่อเจาะระบบสเปรดชีต
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * อัปเดตฟังก์ชัน `sanitizeInput` ใน `backend.gs` ให้ทำการตัดช่องว่าง (Trimming/BOM Whitespace) ก่อน แล้วนำมาตรวจสอบหาอักขระพิเศษขึ้นต้น หากพบจะทำการเติมเครื่องหมายอัญประกาศเดี่ยว (Single Quote `'`) นำหน้าสตริงเพื่อบังคับให้ Google Sheets แสดงเป็นข้อความธรรมดา ไม่ใช่สูตรประมวลผล
  * ปรับปรุง Unit Test ในฝั่ง Client เพื่อจำลองตรรกะเดียวกันนี้ ทำให้ตรวจจับความถูกต้องได้อย่างสมบูรณ์

---

## 🕳️ 4. ปัญหาบันทึกข้อมูลล้มเหลวอย่างเงียบ (Silent Database Insertion Failure)
* **รหัสอ้างอิง:** SEC-04
* **ผลการตรวจสอบ (Observation):**
  * ไคลเอนต์และเซิร์ฟเวอร์ส่งข้อมูลในรูปแบบที่ไม่สอดคล้องกัน (Nested Payload vs Flat Structure) และฝั่งไคลเอนต์เรียกใช้โหมด `mode: "no-cors"` ทำให้เบราว์เซอร์พรางข้อผิดพลาดข้ามไซต์ และแจ้งผู้ใช้ว่าบันทึกสำเร็จแม้เกิดข้อผิดพลาดรันไทม์บน Apps Script
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ลบโหมด `no-cors` ออกจากคำขอส่งข้อมูลทั้งหมดใน `api.ts`
  * ปรับจูนโครงสร้าง API payload ให้ตรงกันระหว่าง Frontend และ Backend และเขียนตัวดักจับสถานะผลลัพธ์เครือข่าย เพื่อให้แสดงกล่องข้อความเตือนเมื่อข้อมูลล้มเหลวอย่างโปร่งใส

---

## 🔒 5. การขาดการควบคุมสิทธิ์ในการเขียนข้อมูล (Lack of Write Authorization on API POST)
* **รหัสอ้างอิง:** SEC-05
* **ผลการตรวจสอบ (Observation):**
  * คำสั่ง `saveBatch` หรือ `deleteLog` ใน `doPost(e)` ไม่ตรวจสอบว่าผู้ส่งข้อมูลได้รับการลงชื่อเข้าใช้งานจริง ส่งผลให้ระบบเสี่ยงต่อการถูกสแปมหรือทำลายข้อมูลจากภายนอก
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * บังคับให้ตรวจสอบสิทธิ์ผ่านฟังก์ชัน `verifySessionToken(auth.sessionToken)` ใน `doPost` ก่อนจะเริ่มเข้าประมวลผลคำสั่งสำคัญ เช่น บันทึก ลบ หรือส่งข้อเสนอแนะ

---

## 🔒 6. ปัญหารันไทม์ตัวแปร `today` ถูกอ้างอิงก่อนการประกาศ (ReferenceError: `today is not defined`)
* **รหัสอ้างอิง:** SEC-06
* **ผลการตรวจสอบ (Observation):**
  * ตัวแปร `today` ถูกประกาศไว้ในเงื่อนไขวันทำงาน หากไม่ได้ตั้งจำกัดวันทำงาน ตัวแปร `today` จะกลายเป็น `undefined` (ผลจาก Variable Hoisting) ส่งผลให้การเช็คเวลาหมดอายุของ OTP คืนค่าเป็นเท็จเสมอ และข้ามเวลาหมดอายุไปได้
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ประกาศและระบุค่าเริ่มต้นให้ตัวแปร `var today = new Date();` เป็นคำสั่งแรกสุดของฟังก์ชัน `verifySessionToken` และ `verifyOTP`

---

## 🔒 7. การฝังไอดีฐานข้อมูลในโค้ด (Hardcoded Spreadsheet ID)
* **รหัสอ้างอิง:** SEC-07
* **ผลการตรวจสอบ (Observation):**
  * การฝัง Spreadsheet ID เริ่มต้นในไฟล์ `backend.gs` เสี่ยงต่อการรั่วไหลหากซอร์สโค้ดถูกอัปโหลดสาธารณะ
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ปรับปรุงให้ดึงค่า Spreadsheet ID จากระบบจัดเก็บคุณสมบัติ `PropertiesService.getScriptProperties().getProperty("SPREADSHEET_ID")` โดยไม่มีการฝังไอดีเริ่มต้นไว้ในโค้ดจริง

---

## 🔒 8. ช่องโหว่ Mock Token Bypass บน Production Code
* **รหัสอ้างอิง:** SEC-08
* **ผลการตรวจสอบ (Observation):**
  * การตรวจสอบ `sessionToken === "mock-token-123"` เพื่อข้ามระบบล็อกอินในการพัฒนา ถูกวางไว้โดยไม่มีตัวควบคุมความปลอดภัย
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ปรับปรุงเงื่อนไขใน `backend.gs` โดยจะยอมรับ Mock Token ได้ก็ต่อเมื่อผู้ดูแลระบบตั้งค่าคุณสมบัติ `ALLOW_MOCK_TOKEN` เป็นสตริง `"true"` ในระบบหลังบ้านเท่านั้น ป้องกันการใช้งานบนระบบจริง

---

## 🔒 9. ขาดระบบควบคุมอัตราการขอ OTP (No Rate Limiting for OTP Requests)
* **รหัสอ้างอิง:** SEC-09
* **ผลการตรวจสอบ (Observation):**
  * ไม่มีสคริปต์ควบคุมปริมาณการส่งคำขอ OTP (Rate Limiter) ต่อหนึ่งอีเมล ทำให้ระบบเสี่ยงต่อการโดน OTP Flooding
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * เพิ่มตรรกะในฟังก์ชัน `requestOTP` บันทึกเวลาขอ OTP ล่าสุดลงในตารางสเปรดชีต และปฏิเสธการขอรหัสใหม่หากเวลาห่างจากรอบก่อนหน้าไม่ถึง 60 วินาที พร้อมเพิ่มตรรกะจำกัดจำนวนครั้งที่ทดลองเดารหัสผิดพลาด (สูงสุด 3 ครั้ง) ในฟังก์ชัน `verifyOTP`
