# WCAG 2.2 AA Accessibility Audit & Remediation Guide / รายงานผลการตรวจสอบการเข้าถึงข้อมูลตามมาตรฐาน WCAG 2.2 AA

เอกสารฉบับนี้แสดงรายงานผลการประเมินความสะดวกในการเข้าใช้งานเว็บแอปพลิเคชัน (Accessibility Audit) สำหรับผู้ใช้ที่มีข้อจำกัดทางร่างกายหรือผู้ทุพพลภาพ โดยอ้างอิงตามมาตรฐานสากล **Web Content Accessibility Guidelines (WCAG) 2.2 ระดับ AA** พร้อมทั้งสถานะการปรับปรุงแก้ไขที่ดำเนินการแล้วในตัวซอร์สโค้ดปัจจุบัน

---

## 🎨 1. ปัญหาความต่างของสีต่ำกว่าเกณฑ์ (Color Contrast Violations)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 1.4.3 Contrast (Minimum) (ระดับ AA - อัตราส่วนขั้นต่ำ 4.5:1 สำหรับข้อความขนาดปกติ และ 3:1 สำหรับข้อความขนาดใหญ่)
* **รายละเอียดข้อผิดพลาดเดิม:**
  1. **ข้อความสีเทารอง:** การใช้คลาส `.text-gray-500` (หรือ `.text-slate-400` / `.text-slate-500` บนพื้นหลังสว่างและมืด) มีอัตราส่วนความต่างสีต่ำกว่าเกณฑ์ 4.5:1
  2. **ปุ่มเด่นสีเขียว:** ตัวอักษรสีขาวบนพื้นหลังปุ่มสีเขียว `bg-green-600` มีอัตราคอนทราสต์ต่ำกว่าเกณฑ์
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ปรับระดับสีเทาที่ใช้แสดงผลข้อความรองทั้งหมดให้มีความเข้มเพิ่มขึ้นในโหมดสว่าง (เช่น `text-slate-600` หรือ `text-gray-700`) และสว่างขึ้นในโหมดมืด (เช่น `dark:text-slate-300`)
  * ปรับพื้นหลังปุ่มสีเขียวหลักไปใช้สีเขียวเข้มที่ให้ความต่างสีผ่านเกณฑ์ เช่น `bg-green-700` หรือปรับเปลี่ยนความเข้มเพื่อรองรับตัวอักษรสีขาวที่อัตราส่วนขั้นต่ำ 4.5:1 อย่างปลอดภัย

## 🏷️ 2. การขาดคุณสมบัติ ARIA และการสื่อความหมายข้อมูล (Incorrect / Missing ARIA Attributes)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 1.3.1 Info and Relationships, 4.1.2 Name, Role, Value
* **รายละเอียดข้อผิดพลาดเดิม:**
  1. **ชุดควบคุมแถบแท็บข้อมูล (Tab Controls):** ปุ่มกดสลับหน้างานขาดการระบุบทบาทคุณลักษณะ ARIA ทำให้อุปกรณ์ Screen Reader ไม่เข้าใจความสัมพันธ์
  2. **ปุ่มไอคอนออกจากระบบไม่มีข้อความชื่อ (Icon-only Button):** ปุ่มไม่มีคำอธิบาย ทำให้ออกเสียงเพียงคำว่า "button" เปล่า ๆ
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ติดตั้งบทบาท `role="tablist"` บนแถบเลือกแท็บ และกำหนดคุณสมบัติ `role="tab"`, `aria-selected={activeTab === 'tabId'}`, และ `aria-controls` บนปุ่มสลับแต่ละแท็บ
  * เพิ่ม `aria-label` บนทุกปุ่มที่มีเฉพาะไอคอน (เช่น `aria-label="ออกจากระบบ"`, `aria-label="ปิด"`)
  * กำหนดโครงสร้าง `role="tabpanel"` และ `aria-labelledby` ให้สอดประสานกันในคอนเทนเนอร์แสดงผลเนื้อหา

## ⌨️ 3. การตัดตัวบ่งชี้โฟกัสของคีย์บอร์ดออก (Suppression of Keyboard Focus Outlines)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 2.4.7 Focus Visible (ระดับ AA - ทุกอิลิเมนต์ที่รับโฟกัสได้ผ่านคีย์บอร์ด ต้องมีตัวบ่งชี้โฟกัสที่มองเห็นได้ชัดเจน)
* **รายละเอียดข้อผิดพลาดเดิม:**
  * มีการใช้งานคลาสสไตล์เพื่อยกเลิกโฟกัสริงปกติ เช่น `focus:border-transparent outline-none` ส่งผลให้ผู้ใช้ที่นำทางด้วยแป้นพิมพ์ Tab / Shift+Tab มองไม่เห็นตำแหน่งโฟกัสปัจจุบัน
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ห้ามใช้คลาสปิด outline โดยไม่มีตัวบ่งชี้ทดแทน และดำเนินการใส่สไตล์โฟกัสริงเด่นชัดแบบเฉพาะเจาะจงผ่านคุณสมบัติ `focus-visible` ของ Tailwind CSS เช่น:
    ```html
    focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-purple-500 focus-visible:outline-none
    ```

## 🔗 4. เลเบลและช่องกรอกข้อมูลไม่เชื่อมโยงกัน (Semantic HTML Label-Input Decoupling)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 1.3.1 Info and Relationships, 3.3.2 Labels or Instructions
* **รายละเอียดข้อผิดพลาดเดิม:**
  * แท็ก `<label>` และ `<input>` / `<select>` ขาดคุณสมบัติ `htmlFor` และ `id` ที่ตรงกันเพื่อเชื่อมโยงความหมาย
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ผูกและตรวจสอบการใช้งาน `htmlFor` บนตัวเลเบลคู่กับคุณสมบัติ `id` ของช่องรับข้อมูลให้สัมพันธ์และตรงกันในทุกแบบฟอร์มบันทึกรายการ (Run, Sort, External)

---

## ⌨️ 5. ปัญหา Event Bubbling บนคีย์บอร์ด และ Focus Trap ใน Modal
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 2.1.1 Keyboard (การเข้าถึงคีย์บอร์ด), 2.4.3 Focus Order (การเรียงลำดับโฟกัส)
* **รายละเอียดข้อผิดพลาดเดิม:**
  1. การกด Enter หรือ Space บนปุ่มเพิ่ม/ลดจำนวนพัสดุ สะท้อนขึ้นไป Uncheck แถวรายการพัสดุในหน้า RunPage
  2. คีย์บอร์ดสามารถเล็ดลอดออกจากหน้า Modal ตรวจสอบผลลัพธ์การบันทึกได้ และไม่มีปุ่มปิดลัดผ่าน Escape
* **สถานะการแก้ไข:** 🟢 **แก้ไขแล้ว (Resolved)**
* **แนวทางการแก้ไขที่ดำเนินการ:**
  * ใส่คำสั่ง `e.stopPropagation()` บนอิลิเมนต์จัดการจำนวนและฟิลด์อินพุตปรับปรุงจำนวน ป้องกัน Event Bubbling
  * ติดตั้ง Focus Trap (ระบบวนโฟกัส) ภายใน [ReceiptModal.tsx](./src/components/common/ReceiptModal.tsx) และดักจับแป้นพิมพ์ปุ่ม `Escape` เพื่อเปิดปิดการปิดหน้า Modal อย่างเหมาะสม
