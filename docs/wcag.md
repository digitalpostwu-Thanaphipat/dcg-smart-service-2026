# WCAG 2.2 AA Accessibility Audit & Remediation Guide / รายงานผลการตรวจสอบการเข้าถึงข้อมูลตามมาตรฐาน WCAG 2.2 AA

เอกสารฉบับนี้แสดงรายงานผลการประเมินความสะดวกในการเข้าใช้งานเว็บแอปพลิเคชัน (Accessibility Audit) สำหรับผู้ใช้ที่มีข้อจำกัดทางร่างกายหรือผู้ทุพพลภาพ โดยอ้างอิงตามมาตรฐานสากล **Web Content Accessibility Guidelines (WCAG) 2.2 ระดับ AA** จากการตรวจสอบไฟล์แอปพลิเคชันหลัก `wus-track/src/assets/App.tsx`

---

## 🎨 1. ปัญหาความต่างของสีต่ำกว่าเกณฑ์ (Color Contrast Violations)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 1.4.3 Contrast (Minimum) (ระดับ AA - อัตราส่วนขั้นต่ำ 4.5:1 สำหรับข้อความขนาดปกติ และ 3:1 สำหรับข้อความขนาดใหญ่)
* **รายละเอียดข้อผิดพลาด (Observations):**
  1. **ข้อความสีเทารอง (Secondary text):** ในไฟล์ `App.tsx` มีการระบุคลาส `.text-gray-500` (โค้ดสี `#6B7280` บนพื้นหลังสีขาว `#FFFFFF`) เช่น บรรทัดที่ 126 และแถบเมนูแท็บที่ไม่ได้เลือก มีค่าอัตราส่วนความต่างสีเพียง **4.01:1** ซึ่งต่ำกว่าเกณฑ์ขั้นต่ำ 4.5:1
  2. **ข้อความคำแนะนำเพิ่มเติม (Help/Informational text):** มีการใช้งานคลาส `.text-gray-400` (โค้ดสี `#9CA3AF` บนพื้นหลังสีขาว `#FFFFFF`) เช่น บรรทัดที่ 135 ในส่วนท้ายของฟอร์ม มีค่าอัตราส่วนความต่างสีแย่มากเพียง **2.5:1**
  3. **ข้อความบนปุ่มหรือสถานะที่ถูกเลือก (Selected Active Elements):** อ้างอิงตามข้อกำหนด `GEMINI.md` โทนสีเน้นย้ำ (Accent Color) ของโครงการคือสีเขียว OLED (`#22C55E`) เมื่อนำข้อความสีขาว (`#FFFFFF`) ไปแสดงทับลงบนพื้นหลังสีเขียวนี้ จะให้ความต่างสีเพียง **2.3:1** ซึ่งไม่ผ่านเกณฑ์มาตรฐานอย่างร้ายแรงและทำให้อ่านข้อมูลได้ยากมาก
* **แนวทางการแก้ไข (Remediation Instructions):**
  * **สำหรับตัวอักษรสีเทา:** เปลี่ยนไปใช้สีกรองตัวอักษรที่เข้มขึ้น โดยปรับ `.text-gray-500` เป็น `.text-gray-700` (`#374151` อัตราส่วน 9.4:1) หรืออย่างต่ำสุดคือ `.text-gray-600` (`#4B5563` อัตราส่วน 6.2:1) และปรับจาก `.text-gray-400` เป็น `.text-gray-600`
  * **สำหรับปุ่มสีเขียวเด่น (`#22C55E`):**
    * *ทางเลือกที่ 1:* เปลี่ยนสีตัวอักษรบนปุ่มเป็นสีดำเข้ม (`#000000`) หรือสีน้ำเงินเข้มจัด เพื่อให้ได้ค่าคอนทราสต์ 9.1:1
    * *ทางเลือกที่ 2:* ปรับพื้นหลังปุ่มสีเขียวให้มีความเข้มสูงขึ้น เช่น ใช้สีเขียวป่าไม้เข้ม (`#15803d` หรือ `#166534`) เพื่อให้สามารถวางข้อความสีขาวซ้อนทับได้อย่างปลอดภัยและผ่านเกณฑ์ 4.5:1

## 🏷️ 2. การขาดคุณสมบัติ ARIA และการสื่อความหมายข้อมูล (Incorrect / Missing ARIA Attributes)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 1.3.1 Info and Relationships, 4.1.2 Name, Role, Value
* **รายละเอียดข้อผิดพลาด (Observations):**
  1. **ชุดควบคุมแถบแท็บข้อมูล (Tab Controls):** แถบปุ่มกดสลับระหว่างหน้าจอในบรรทัดที่ 153–159 ขาดการใช้งานคุณสมบัติ ARIA ที่เป็นมาตรฐาน ส่งผลให้ตัวอ่านหน้าจอ (Screen Reader) ไม่ทราบโครงสร้างการทำงาน
  2. **กล่องแสดงเนื้อหาตามแท็บ (Tab Content Panels):** ส่วนบรรทัดที่ 170, 204, 222 แสดงผลเนื้อหาโดยไม่มีการกำหนดความสัมพันธ์กับปุ่มกดที่เลือก
  3. **ปุ่มไอคอนออกจากระบบไม่มีข้อความชื่อ (Icon-only Button):** ปุ่มออกจากระบบในบรรทัดที่ 147–149 มีเพียงป้ายไอคอนของไลบรารี Lucide:
     ```typescript
     <button onClick={handleLogout}><LogOut size={20} /></button>
     ```
     เนื่องจากไม่มีข้อความบอกคำสั่ง ทำให้ Screen Reader อ่านออกเสียงได้เพียงคำว่า "button" เปล่า ๆ โดยผู้ใช้ที่พิการทางสายตาจะไม่ทราบเลยว่าปุ่มนี้ใช้ทำอะไร
  4. **กล่องแจ้งสถานะแบบพลวัต (Status Banners):** ข้อความประกาศผลบันทึกสำเร็จหรือข้อผิดพลาด (บรรทัดที่ 162–167) ขาดการกำหนด Live Regions ทำให้เมื่อเกิดเหตุการณ์ขึ้น ตัวอ่านหน้าจอจะไม่ประกาศข้อความให้ผู้ใช้รับรู้ทันที
* **แนวทางการแก้ไข (Remediation Instructions):**
  * **ปรับปรุงโครงสร้าง Tab Component:**
    * ครอบแถบปุ่มเลือกแท็บด้วยอิลิเมนต์ที่มี `role="tablist"`
    * ใส่ `role="tab"`, `aria-selected={activeTab === 'tabId'}` และ `aria-controls="panel-id"` บนปุ่มกดแต่ละปุ่ม
    * ใส่ `role="tabpanel"`, `id="panel-id"` และ `aria-labelledby="tab-id"` บนส่วนคอนเทนเนอร์เนื้อหา
  * **ปุ่มกดแบบมีไอคอนอย่างเดียว:** เพิ่มคุณสมบัติ `aria-label="ออกจากระบบ"` หรือใส่กล่องซ่อนตัวอักษรสำหรับ screen reader (`.sr-only`) เข้าไปด้านใน:
    ```typescript
    <button onClick={handleLogout} aria-label="ออกจากระบบ">
        <LogOut size={20} />
    </button>
    ```
  * **กล่องประกาศสถานะการทำงาน:** ใส่ `aria-live="polite"` หรือกำหนด `role="status"` เพื่อให้เกิดการแจ้งเตือนเสียงพูดอัตโนมัติเมื่อข้อความในกล่องเปลี่ยนไป

## ⌨️ 3. การตัดตัวบ่งชี้โฟกัสของคีย์บอร์ดออก (Suppression of Keyboard Focus Outlines)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 2.4.7 Focus Visible (ระดับ AA - ทุกอิลิเมนต์ที่รับโฟกัสได้ผ่านคีย์บอร์ด ต้องมีตัวบ่งชี้โฟกัสที่มองเห็นได้ชัดเจน)
* **รายละเอียดข้อผิดพลาด (Observations):**
  * ในไฟล์ `App.tsx` บรรทัดที่ 252 (รวมถึงอินพุตฟิลด์ต่าง ๆ) มีการระบุคลาสเพื่อตัดโฟกัสริงธรรมชาติของเบราว์เซอร์ออกโดยตั้งใจ:
    ```css
    .input-field { ... focus:border-transparent outline-none ... }
    ```
  * ปุ่มสลับแท็บ ปุ่มวงกลม ปุ่มตกลง และช่องกรอกข้อมูลทั้งหมดไม่มีการออกแบบสไตล์ทดแทนเมื่อมีการเปลี่ยนตำแหน่งด้วยการกดปุ่ม Tab บนคีย์บอร์ด
* **ผลกระทบ (Impact):** Visually Critical for Keyboard Users. ผู้ใช้ที่ไม่สามารถใช้เมาส์ได้และจำเป็นต้องนำทางหน้าเว็บผ่านแป้นคีย์บอร์ด (Tab / Shift+Tab) จะมองไม่เห็นเลยว่าตอนนี้จุดโฟกัสงานกำลังทำงานอยู่ที่กล่องข้อความหรือปุ่มใด ทำให้ไม่สามารถใช้งานเว็บแอปพลิเคชันได้เลย
* **แนวทางการแก้ไข (Remediation Instructions):**
  * ห้ามล้างค่า `outline-none` โดยไม่มีการทำ Focus Indicator ชดเชยเด็ดขาด
  * แนะนำให้เขียนสไตล์ครอบคลุมโดยอ้างอิงพฤติกรรม `:focus-visible` ของ Tailwind เพื่อให้โฟกัสริงแสดงขึ้นมาอย่างโดดเด่นเฉพาะเมื่อใช้งานแป้นพิมพ์นำทาง:
    ```html
    focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-green-500 focus-visible:outline-none
    ```

## 🔗 4. เลเบลและช่องกรอกข้อมูลไม่เชื่อมโยงกัน (Semantic HTML Label-Input Decoupling)
* **เกณฑ์ WCAG ที่เกี่ยวข้อง:** 1.3.1 Info and Relationships, 3.3.2 Labels or Instructions
* **รายละเอียดข้อผิดพลาด (Observations):**
  * ส่วนฟอร์มต่าง ๆ ในแอปพลิเคชัน มีการใช้ป้ายชื่อกำกับหน้าช่องข้อความ เช่น `<label>` แต่ไม่ได้มีการผูกความสัมพันธ์เข้ากับกล่องข้อความอินพุต `<input>` หรือตัวเลือกคอมโบ้บ็อกซ์ `<select>` ด้านล่าง ตัวเลเบลไม่มีคุณสมบัติ `htmlFor` และอินพุตไม่มีการตั้งค่า `id` ที่สอดรับกัน
* **ผลกระทบ (Impact):** Medium. เมื่อผู้ใช้งานนำหน้าจอไปกดคลิกที่ตัวอักษรของเลเบล เคอร์เซอร์จะไม่วิ่งไปโฟกัสที่ช่องกรอกข้อมูลโดยอัตโนมัติ และทำให้ตัวอ่านหน้าจอเกิดการอ่านสับสนหรือไม่อ่านเชื่อมต่อชื่อช่องส่งผลให้เข้าใจวัตถุประสงค์อินพุตผิดพลาด
* **แนวทางการแก้ไข (Remediation Instructions):**
  * ทุกอินพุตควบคุมต้องระบุ `id` ที่เป็นเอกลักษณ์ และต้องผูกคู่ตัวอักษรกำกับด้วยคุณสมบัติ `htmlFor` ให้มีค่าตรงกันเสมอ ตัวอย่างเช่น:
    ```typescript
    <label htmlFor="input-dept-name">ชื่อแผนก/หน่วยงาน</label>
    <select id="input-dept-name" value={deptName} onChange={e => setDeptName(e.target.value)}>
        ...
    </select>
    ```
